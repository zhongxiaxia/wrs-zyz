# Fruit_picker_project 项目说明

`Fruit_picker_project` 是一个采摘机器人控制框架，主要用于把真实机器人的底层能力封装成硬件 API，并通过三层嵌套状态机统一调度整个采摘流程。

这个项目目前不是完整业务系统，而是从真实机器人工程中剥离出来的控制层。后续开发主要围绕：

- 补全底层硬件 API
- 完善状态机跳转逻辑
- 让状态机能够稳定驱动真实机器人动作

## 项目目标

项目的核心目标有两个：

1. **封装机器人底层接口**
   - 底盘移动
   - 机械臂控制
   - 相机识别
   - 升降机控制

2. **用状态机组织采摘流程**
   - 外层：`MOVE`，负责移动嵌套
   - 中层：`LIFT`，负责升降机逐层控制
   - 内层：`ARM`，负责机械臂采摘动作

## 当前目录结构

- `main.py`
  - 程序入口，负责创建机器人上下文并启动状态机主循环

- `config.py`
  - 全局配置文件，保存 IP、模型路径、升降参数等

- `fsm/`
  - 状态机实现
  - `robot_context.py`：状态机上下文，保存共享状态和硬件实例
  - `state.py`：定义各个状态类

- `hardware/`
  - 硬件 API 层
  - `chassis_api.py`：底盘控制
  - `arm_api.py`：机械臂控制
  - `camera_api.py`：视觉识别
  - `lift_api.py`：升降机控制

## 状态机设计思路

### 1. 外层 `MOVE`

外层用于模拟机器人在不同采摘区域之间移动。

当前设置：

- `MOVE` 循环 3 次
- 每次 `MOVE` 结束后进入 `LIFT`
- 3 次循环完成后退出到 `IDLE`

### 2. 中层 `LIFT`

中层是当前最重要的部分，用于控制升降机按层移动。

逻辑为：

- 升降机从最低位开始
- 每次上升一个固定步长
- 每一层进入一次 `ARM`
- `ARM` 完成后返回 `LIFT`
- 到达最高位后直接回到底部
- 然后退出中层，回到 `MOVE`

### 3. 内层 `ARM`

内层代表机械臂采摘动作。

当前仍以框架为主，未来会承载：

- 机械臂移动到目标点
- 抓取果实
- 放入篮筐
- 返回观测位

## 升降机 API 约定

升降机接口已经对齐真实机器人通信方式，主要特点如下：

- 使用 `POST /woosh/ros/CallAction`
- 动作字段使用 `lift_control3`
- 目标高度单位为**米**
- 请求中包含 `speed=0.03`
- 发送动作后需要轮询 `POST /woosh/ros/Feedbacks`
- 根据反馈中的 `action == "woosh.ros.action.LiftControl3"` 判断动作状态

### 升降机运行规则

- **上升**：按设定目标高度逐层上升
- **回底**：到达最高位后直接回到底部，不再一层一层下降
- **状态机内部使用毫米**
- **接口请求使用米**

这意味着所有修改升降逻辑的代码都必须注意单位换算。

## 当前状态行为约定

### `INIT`

- 升降机归底
- 机械臂归安全位
- 重置状态机变量
- 跳到 `MOVE`

### `MOVE`

- 计数循环
- 运行 3 次后退出到 `IDLE`
- 每次进入后触发一次 `LIFT`

### `LIFT`

- 中层初始化只做一次
- 每次上升一个固定步长
- 进入 `ARM`
- 到顶后直接回到底部
- 返回 `MOVE`

### `ARM`

- 机械臂采摘占位
- 完成后返回 `LIFT`

### `IDLE`

- 等待任务
- 当前作为结束或空闲状态

### `ERROR`

- 停止动作
- 进入故障模式

### `SHUTDOWN`

- 安全收尾
- 机械臂归位
- 升降机回底
- 退出程序

## 修改代码时的建议

当你修改这个项目时，建议优先遵守以下原则：

1. **不要把状态机写成一次性流程**
   - 它本质上是一个状态跳转系统，不是线性脚本

2. **不要在状态类里直接写网络请求**
   - 硬件通信应该放在 `hardware/` 目录中

3. **不要破坏中层 `LIFT` 的逐层控制逻辑**
   - 这是当前已经验证有效的核心流程

4. **不要混淆毫米和米**
   - 这是最容易导致机器人动作异常的问题

5. **新增 API 时优先考虑是否需要反馈轮询**
   - 真实机器人通常需要“发命令 + 看反馈”才能确认动作完成

## 一句话总结

`Fruit_picker_project` 是一个用于果实采摘机器人的状态机控制框架，核心任务是通过 `MOVE -> LIFT -> ARM` 的三层嵌套结构，逐步调度底盘、升降机和机械臂，并通过硬件 API 与真实机器人通信，实现可扩展的采摘流程控制。
