# Gradient-NBV 在 Windows/WRS 中的 MVP 补全方案

日期：2026-10-21。状态：论文、官方源码及本地代码审计后的实施建议；尚未实现新的梯度规划器。

## 1. 结论与边界

当前 v0 是可运行的采样式 NBV 仿真原型，已具备 RGB-D、点云、概率体素、
整株场景和腕部相机机械臂检查。它可以作为继续开发的平台，但目前还不能称为
论文核心 Gradient-NBV 方法的 MVP 复现：视角选择仍是候选采样加逐个评分，
缺少语义收益、沿途遮挡累积、可微采样及视角梯度优化。

建议保持 Windows、WRS 和原生 PyTorch，替换 ROS 的接口与执行层，保留论文
方法的数学主干。无需先迁移整个 ROS/Gazebo，也无需先训练 DQN。
v1 继续只作为场景、手眼及机器人适配来源；其球面四动作和学习策略不属于本论文的方法。

本次仅新增审计材料和小型诊断脚本，没有修改 v0/v1 的运行算法、安装 ROS、
训练模型、开展新的 NBV 性能实验或执行实体机器人动作。

## 3. 原方法需要保留什么

论文针对已粗略知道位置的单个植物节点，优化相机位置和注视点，形成 5 自由度
视角。不是把整株植物扫得越完整越好，也不是固定半径球面上的四方向动作选择。
论文允许已知粗 ROI，因此 MVP 不需要先实现全局搜索才能开始。

其核心链路是：可见目标分割及 RGB-D → 多视角语义占据图 → 可微射线采样 →
带遮挡的语义信息收益 → 梯度更新视角 → 移动并获取新观测。

每个体素保留占据概率 `p_o`、语义类别、语义概率 `p_s` 和 ROI 标记。
其中 `p_o` 描述几何遮挡，`p_s` 描述目标语义不确定性；二者不能合并为一个概率。
论文在固定 ROI 内将语义概率初始化为 0.5，ROI 外初始化为接近零；整个上下文
地图的占据概率初始为 0.5，再从实际深度观测建立遮挡结构。

论文公式的收益为：

```text
H_s(i) = -p_s(i) log2 p_s(i) - (1-p_s(i)) log2 (1-p_s(i))
T(i)   = product_{j<i} (1-p_o(j))
G(xi)  = sum_r sum_i T_r(i) H_s,r(i)
xi     = {camera_position, look_at_point}
```

沿射线保留多个采样点，使用三线性插值读取地图，保持从视角参数到收益的
计算链可微；地图融合和 WRS 碰撞检查本身不必可微。固定当前观测得到的地图，
对视角参数求梯度即可，不需要对整个 Panda3D 渲染器反向传播。

## 4. 当前实现与论文的实际差距

| 项目 | 当前 v0 | 补全要求 |
| --- | --- | --- |
| 场景和执行 | 已复用 v1 整株模型、Realman、小车、手眼及 IK/FK/碰撞检查 | 保留；后续使用实际 FK 相机姿态闭环 |
| 规划目标 | `pepper.stl` 的果实 AABB 是规划 ROI | 明确改为果梗/拟切割节点附近的粗 ROI；整果探索单列为另一任务 |
| 地图范围 | 主入口网格只覆盖单果/梗及少量边界 | 上下文占据图应包含相机到 ROI 之间的枝叶遮挡；ROI 仅限制目标语义收益 |
| 语义来源 | 机械臂入口依已知 AABB 赋类别、置信度设 1；YOLO 入口的体素标签同样来自 AABB | 区分已知先验与感知；接入可见像素 mask、置信度、深度及跨视角目标身份 |
| 语义融合 | `update_semantics()` 逐点覆盖旧值 | 同类融合置信度、处理类别冲突，并记录是否真实观测过 |
| 评分 | 占据概率熵加目标类别计数 | 使用目标语义熵与沿途遮挡透过率 |
| 射线 | `return_first_only=True` 返回进入 AABB 后首个有效体素 | 多点采样、三线性插值、累计遮挡，不只取首格 |
| 梯度 | Tensor 转 NumPy、整数索引、最终 `.item()`/float | 主计算链保留 Tensor，收益对相机位置/注视点可求导 |
| 视角更新 | 12 个圆周点加 8 个局部平面点，按分数排序 | 局部连续梯度更新；旧采样法保留作基线 |
| 融合时序 | 渲染循环持续融合，按 M 时又融合一次 | 每个明确的传感器帧只融合一次，优化期间冻结地图 |
| 评价 | 主要是窗口及单步移动检查 | 自动回合、对照、逐视角感知质量、时间与轨迹指标 |

### 4.1 已运行的小型诊断

诊断使用 CPU 上的合成体素图，不建立 WRS 窗口、不移动机器人。

1. 在当前 `SimpleNBVGPU` 的地图内、ROI 前方加一面高占据墙，分数从
   `42.87106094360352` 到同一个值；在 ROI 内更深处加入墙，分数也不变。
   这验证了该构造中首格查询没有利用沿途或后续遮挡，不能理解为有效可见性模型。
2. 固定占据和类别，将目标语义概率从 0.01 改为 0.5，分数不变。
   代码也确认评分读取的是占据概率和类别，没有读取 `sem_prob`。
3. 世界坐标略低于网格下界，`world_to_index()` 因向零截断返回索引 0 且 valid 为真。
   应使用 floor 并检查物理边界。
4. 两条终点深度分别为 0.2 m、0.8 m 的射线，空闲空间更新统一截到最短射线：
   命中 y 索引为 20、80，但空闲更新最大仅到 19，较远射线后半段没有更新。
   端点距离小于一个体素时还触发空数组最小值异常。
   独立核查还指出：近点混入远点时，统一的正截断距离可能使近射线越过自身
   hit 继续刻空；每条射线都需要独立的有效长度和终点前截断。

因此先保证地图和收益的物理含义，再加梯度；只增加候选数或给当前函数加
`requires_grad=True`，无法解决这些差距。

## 5. 官方公开代码也需要辨别

不要将公开演示默认值直接当作论文实验协议。固定快照中存在以下明确差别：

| 内容 | 论文 | 固定快照代码 |
| --- | --- | --- |
| 遮挡透过率 | 直接累计 `1-p_o` | `sigmoid(1e7*(p_o-0.51))` 转 opacity 后再累计 |
| 优化形式 | 梯度上升，实验步长 0.065 | `-log(mean(ray_gains)+eps)`，AdamW 学习率 0.03 |
| ROI 尺寸 | 边长 0.06 m | 每轴中心 ±25 格，默认 0.003 m 体素下未裁剪时边长 0.15 m |
| 射线近远界 | 0.10–0.75 m | VoxelGrid 默认 0.05–0.60 m |
| 感知 | Mask R-CNN 节点实例分割 | 默认 `Perceiver` 使用红色阈值分割的 toy 示例 |
| 多视角关联 | Kalman 位置更新及类别投票 | 本次核对的默认执行链没有接入该跟踪步骤 |

官方 `raysampler.py` 还有 Gazebo 专用 optical-frame 变换与硬编码 0.024 m
偏移。WRS 中应使用当前真实手眼及 Panda/OpenCV 变换，不复制该偏移。

建议记录 `visibility_mode`、`optimizer_mode` 和全部物理尺寸：

- `reference`：按该提交的 opacity、损失和优化器做核心数值对拍。
- `paper`：按论文公式和物理参数实现，并明确其与代码的差别。
- 更平滑的 opacity、回溯缩步等作为 WRS 适配配置，单独命名和比较。

`reference` 中的阈值将未知 `p_o=0.5` 近似视为可透过，与论文直接相乘并不相同。
原样采用论文式时，连续未知体素会使透过率快速衰减；采用极陡 sigmoid 又可能
使占据通道的梯度饱和。二者都需要数值验证，不能默默混成一个“原论文公式”。
固定射线数量下，最大化总收益与最小化负对数均值选择相同的最优视角；
负对数本身会反转数值排序，并改变梯度尺度。AdamW 和普通梯度步的更新轨迹
也不能不经验证视为等价。

### 5.1 ROS 运行层如何替换

| 官方运行层 | Windows/WRS 对应接口 |
| --- | --- |
| Gazebo 场景及 ROS RGB-D 消息 | WRS/Panda3D 场景及 `VirtualDepthCamera` 的 RGB-D/内参 |
| TF / optical-frame 外参 | 现有手眼文件、`RealmanAdapter.camera_pose()` 及明确的 CV/Panda 转换 |
| ROS 服务、MoveIt 执行 | 普通 Python 调用与 RealmanAdapter 的 IK/FK/限位/路径碰撞检查；绕障规划另行增加 |
| RViz 展示 | Panda3D 点云/体素/轨迹与 OpenCV 图像 |
| PyTorch 地图与可微收益 | 保留数学流程，去除 ROS/RViz 导入及 Gazebo 特例 |

当前 WRS 适配是离散关节路径检查，不能在结果中写成已完整等价替换 MoveIt 的
运动规划能力。方法对照时三组必须经过相同的 WRS 执行层。

## 6. Windows/WRS 的分阶段实施

### 阶段一：稳定观测闭环和地图

保留 `pepper_robot_nbv.py` 为主入口，先实现：

```text
capture(frame_id, actual_FK_pose)
  -> visible mask/confidence + aligned depth
  -> integrate_once(frame_id)
  -> frozen planning map
  -> propose next camera pose
  -> IK/FK + joint/path/camera/plant collision checks
  -> commit accepted joint configuration
  -> capture a new frame at the actual FK pose
```

渲染只显示，不重复增加融合证据。一次规划对所有候选或梯度试探使用同一张地图。
修复按各自终点长度更新 free-space、坐标 floor、越界、无效深度和 hit/free 冲突。
同一帧按体素聚合，避免像素密度或重复索引造成不受控的置信度增加。

已知粗 ROI 可由手动指定或现有候选节点位置提供，必须记录来源与偏差；
ROI 中心不是实时检测结果。不能把完整 STL 真值提前填入规划用占据图。
已知整株 mesh 用作碰撞障碍可以作为独立环境先验，必须向全部对照提供同样信息；
它不等于规划器预先知道隐藏节点的几何、身份和精确切点。

验收：相同帧重复提交不改变地图；地图不随窗口刷新次数变化；不同深度射线
正确更新至各自终点；目标前方的叶片在上下文占据图中能被表示。

### 阶段二：共享的可微语义收益

新建纯 PyTorch 计算核心：可微 look-at → 像素射线 → 多点采样 → `grid_sample`
三线性查询 → 语义熵与透过率 → Tensor 标量收益。
v0 现有评分器保留为历史基线；新的 SamplingNBV 与 GradientNBV 共用此收益。

统一米单位、光学 Z 深度/射线长度、Panda 与 OpenCV 坐标、体素中心、
`[N,C,D,H,W]` 的轴序和 `align_corners` 归一化。地图外采样必须有明确有效性处理，
不能把 padding 的零值悄悄当作已知自由空间。语义未知和“没有观测到”也应分开。

验收：单占据平面遮挡其后目标；左右镜像场景的梯度方向相应镜像；移动遮挡物
会改变收益；光滑内部测试点的 autograd 与中心有限差分一致。
用已知线性三维场分别检查各轴插值，用离轴像素检查光学 Z 深度反投影。
硬阈值参考模式的非光滑点应另列，不能要求其通过平滑函数的梯度判据。

### 阶段三：梯度提案与机械臂执行

先用固定注视点、只优化相机三维位置做调试对照，再实现相机位置与注视点的
论文式 5 自由度参数化。固定注视点版本只能称简化消融，不能称完整方法。
注视点优化限制在固定粗 ROI 内；它的数值优化不等同于检测器对节点位置的测量更新。
不应在优化过程中任意移动 ROI 来追逐高分区域。

梯度步使用小范围位置/转角/最小距离约束，再由现有 RealmanAdapter 硬检查。
不可行时缩步、回溯并计入计算和拒绝次数；仍不可行就显式报告本步失败。
只提交通过检查的状态；拒绝后恢复规划参数和必要的优化器状态，并与实际 FK 同步，
不能让优化器继续从未执行成功的“虚拟位置”出发。

MVP 可先保留直接关节插值及采样检查，不要求先写全套绕障规划；无法通过该路径
检查的提案必须拒绝。自由相机只作为数值诊断，不替代机械臂主结果。

验收：固定种子自动运行多个观测步骤，遮挡场景中能产生非零且方向合理的梯度，
存在可行移动时正确执行；不可行时状态不漂移、无静默瞬移。

### 阶段四：接通目标感知及定位

先用单个可见节点 mask 的理想感知模式隔离规划问题，必须标为仿真感知上界。
仅提供当前视角中真正可见的像素及深度，不提供被遮挡的完整形状。
整株 stem/fruit 类别并不自动等同于某个“目标节点”实例。

随后接入分割输出或受深度约束的检测框代理，记录 mask、实例类别和置信度，
从有效目标点估计 3D 均值/不确定度，加入门控关联、目标丢失处理和 Kalman 更新。
检测框全填 0.9 可以作有名称的粗代理，但不能冒充实例分割或真实模型置信度。
不必一开始强制安装原论文的 Detectron2；如果换用其他分割器，应列为感知替代。

### 阶段五：可复现对照和验收

先做单目标加左右/上下挡板的受控场景，再做整株自然遮挡。
三组主对照为 Random、共享收益的 SamplingSemanticNBV、GradientNBV；
原 v0 分数保留为附加旧基线。比较使用相同场景、粗 ROI 偏差、初始状态、
感知输入、地图融合、局部可行动作范围和机器人检查，固定随机种子。
正式 Sampling/Random 在当前视角附近采样，不沿用旧 v0 全周候选作为唯一对照。
主协议可固定已采 RGB-D 观测数，同时统计全部尝试；等时间预算作为另一个协议。
随机重启或采样 fallback 是显式混合策略，必须标记并计入成本。

至少保存逐帧 RGB-D/mask、地图快照或重放输入、实际相机/TCP/关节、目标估计、
提案/接受结果、梯度范数、收益、forward/backward/回溯次数及失败原因。

| 指标 | MVP 要求 |
| --- | --- |
| ROI 覆盖 | 真实观测过的 ROI 体素比例，使用显式 observed 标记；不把插值/先验当观测 |
| 节点感知质量 | 目标表面重建 precision/recall/F1、3D 定位真实误差；有跟踪时另报估计协方差 |
| 计算成本 | 同采样分辨率下的 forward、backward、规划和端到端时间；GPU 计时需同步 |
| 移动成本 | 实际执行相机轨迹长度、转角、拒绝率及最终失败率 |
| 运行预算 | 明确初始观测、接受步、拒绝提案及总预算的计数，不隐藏回溯或 fallback 成本 |

论文按 2 mm 分辨率与 2 mm 重建匹配阈值评价。现有 1 cm 网格不能直接套用其
2 mm F1 宣称复现。可先用较粗配置调通，但将其作为 MVP 配置；最终对齐论文
或将不同分辨率与阈值的结果分开报告。真值 STL 只用于评价和已声明的初始先验，
或作为全部方法共享的已知碰撞障碍，不直接填入未知信息地图或作为隐藏目标测量值。

此阶段不以复现论文“十倍计算优势、28% 轨迹优势”为预设通过条件。
先验收方法链路与公平对照，再报告本机结果；不能用 ray-call 数直接替代真实耗时。

## 7. 本机资源与建议代码组织

小型诊断读取到本机 RTX 3050 Ti、约 4 GB 显存、PyTorch 2.7.1+cu118。
官方 README 的完整演示要求至少 8 GB，不能据此断定核心方法在本机不可实现。
这是资源适配建议，尚未实测新可微规划器的峰值显存或速度。

建议从 80×60 射线、64 个深度采样点调试，随后增加到 128 并检查收益/梯度/轨迹
对分辨率的稳定性。按 ray chunk 分块计算并累积标量的梯度，避免保留全部 chunk
的反向图；射线块间共享同一地图与视角参数，最后只执行一次优化更新。
分块必须按射线数量正确加权，核对分块与未分块的总收益和梯度一致；reference
模式不能把各块的负对数损失直接相加来代替全局负对数均值损失。
低分辨率图像与内参必须成比例缩放且核对像素中心。GPU 规划和分割分阶段安排，
先测显存再增加规模。公平对照必须使用同一配置。

建议新增独立命名的 `gradient_nbv/` 包，避免与 v1 的 `pepper_nbv` 和旧根目录通用
模块名冲突；本次只是目录建议，尚未创建这些运行模块：
